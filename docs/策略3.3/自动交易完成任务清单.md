## 用户最新确认的范围覆盖（2026-11-22）

以下决定优先于本清单中任何较早的冲突记录：

- **允许新增买入的资产：** BTC、PAXG、ETH、BNB、UNI 五种全部允许自动新增现货买入；不得再因旧工作簿审核状态或六项基本面审核记录缺失而拦截。CL仍为signal-only，未列入资产池的未知资产仍默认禁止新增买入。
- **订单类型与价格：** 自动Trader只使用Binance Spot **LIMIT + GTC**。BUY限价为下单前最新有效现货价×1.005，SELL限价为×0.995；BUY按tickSize向下取整，SELL向上取整。不得把旧MARKET入口作为自动交易路径。
- **邮件范围：** 仅需策略信号达标邮件（核心55分/山寨75分）和真实BUY/SELL成交邮件。成交邮件只由交易所确认的真实fill触发；邮件不审批、不需要回复。保留邮件发送功能和Mock自动化测试，**不要求真实SMTP投递测试**，不要求用户提供SMTP授权码用于验收，也不再运行npm run test:smtp。
- **连续运行：** 用户不要求72小时连续运行；以短时启动/停止、订单状态生命周期、部分成交和重启恢复等必要验证替代。
- **密钥：** Binance Testnet Key/Secret仅放在用户本机.env.local，不得发到聊天或提交GitHub。曾在聊天中暴露的旧测试网密钥必须先撤销并重建。

不要把上述比例理解为“已经完成了七成可实盘功能”。真正的上线门槛是全链路验收，而不是代码文件数量。

## 五、生产上线的硬性验收门槛

以下条件必须全部满足，缺一项都不应开启生产自动交易：

- [ ] 策略3.3所有自动执行规则已与代码逐项核对并通过测试。
- [ ] BUY、SELL 在 Testnet 完成完整生命周期演练，包含部分成交与异常恢复。
- [ ] 交易所成交、账户余额、本地持仓/成本账本能够持续对账一致。
- [ ] 未知订单状态绝不盲目重发；账本异常自动暂停相关币种或全局执行。
- [ ] Binance 密钥仅存在于服务端，生产 Key 最小权限且提现/划转关闭。
- [ ] 生产 BUY/SELL 有独立服务端开关、额度上限、紧急停止和审计日志。
- [ ] Simple Earn 赎回若未完成独立验收，必须继续保持关闭，不能阻塞或绕过安全检查。
- [ ] 页面关闭后的执行要求已经明确；若要求无人值守，必须有服务端调度与持久化状态。
- [ ] CI、类型检查、自动化测试、历史/样本外验证和独立风险审查全部通过。
- [ ] 用户明确确认生产环境启用范围、额度、币种和权限。
