# 自动化交易落地路径（本地优先）

> 策略规则唯一依据：根目录 `策略3.3.xlsx` 与用户确认决策。本文只谈工程落地，不改策略参数。

## 用户最终目标

本机 `.env.local` 只需填写专用 Binance Key/Secret 并按运维手册设置模式，启动一个命令后，按策略3.3自动完成 BUY/SELL、止盈、查单对账、成交入账和通知；关闭浏览器仍持续运行。**在下述全部门槛通过前，production 保持硬拒绝。**

## 必须完成的顺序

1. 修复并独立验收 SELL 01A，包括混合冲突 tick 集成测试。
2. 完成 M0 文档/残留清理和策略3.3规则矩阵逐条核验；只记录策略差异，不改Excel参数。
3. 完成 SQLite 并发/fencing/重复成交/Outbox边界测试。
4. 完成 Trader BUY 与 SELL 的服务端闭环；SELL 不得依赖浏览器 IndexedDB。
5. 完成 unknown 订单进程重启恢复：只按原 clientOrderId 查单，绝不重复 POST。
6. 完成只读看板、统一模式、自检、熔断、邮件直发、日志轮转；Earn 未完成前继续保持关闭。
7. 使用专用 Testnet Key完成 BUY/SELL、异常恢复和连续运行验收。
8. Claude独立验收 M0–M3；之后由用户本人决定是否切换 production。

## 安全红线

- 当前 production 模式由代码硬拒绝，不得移除该保护。
- 不得将单元测试或 Mock 结果描述为 Testnet 实测。
- 未知订单只读对账，不得盲目重发。
- 不新增单日/单笔金额上限；按用户确认的策略3.3固定额度执行。
- 真实 Key/Secret 只放本机 `.env.local`，不得粘贴到聊天或提交 Git。
