# 自动化交易落地路径

> 目标：在**策略 3.3**与项目红线约束下，把现有「信号 + 队列 + 预检 + 对账」做成可长期运行的自动交易系统。  
> 分支：`gpt`。生产 BUY/SELL **默认关闭**，先 Testnet 验收。

---

## 一、你现在实际拥有什么

| 能力 | 状态 |
|------|------|
| 周线信号（买/卖/止盈等） | 有 |
| BUY/SELL 队列、预检、clientOrderId、对账 | 有 |
| 资金预留、SELL 底仓保护与部分成交续卖 | 有（持续加固） |
| 浏览器后台节拍（`ExecutionBackground`） | 有，**依赖页面打开** |
| 卖出单次节拍编排（`runSellAutomationTick`） | 有，可单测/复用 |
| 币安测试网真单全链路验收 | **未完成** |
| 页面关闭仍运行的服务端调度 | **未完成** |
| 生产无人值守 | **未达标** |

**结论：** 自动交易的「大脑和手脚」大体在，缺的是 **Testnet 验收** 和 **不依赖浏览器的常驻调度**。

---

## 二、推荐落地顺序（不要跳步开生产）

### 阶段 1 — 规则与安全冻结（进行中）
- 策略只认 `策略3.3.xlsx` + 用户 A2–G2 决策。
- 生产开关保持关；密钥不进仓库。
- 矩阵逐项标「已实现/有测试/实测」。

### 阶段 2 — 浏览器内「半自动」（当前主路径）
1. 打开看板，保持在线。
2. 信号 → 入队 → dry-run 预检 →（仅当显式打开 Testnet LIVE）下单。
3. 对账写入成交 → 通知邮件/Outbox。
4. 用 `runSellAutomationTick` / 现有 Background 做回归。

### 阶段 3 — Binance Spot **Testnet** 端到端（上生产前必做）
对 **BUY 一笔 + SELL 一笔（止盈档）** 至少各跑通：

```text
信号 → 入队 → 预检 → 提交 → 查单 → 成交入账 → 通知 → 队列终态
```

异常必须覆盖：超时未知单、部分成交、拒单。  
**全部用测试网 Key，小额。**

### 阶段 4 — 常驻调度（真正「自动化」）
- 可选：Cloudflare Worker / 小型 VPS 定时拉信号、跑节拍。
- 账本与锁放到服务端（或至少单实例 + 持久化），避免多浏览器抢单。
- 浏览器只做监视与人工复核台。

### 阶段 5 — 生产小额
- 独立生产 Key（无提现）、限额、告警、回滚预案。
- 双人/你本人书面确认后再改 LIVE 开关。

## 三、本仓库内建议你立刻做的操作

1. `git pull origin gpt`  
2. 跑：`npx vitest run lib/execution/sell-*.test.ts`  
3. 配置 **Testnet** API（本地 `.env`，勿提交）。  
4. 仅在 Testnet 将卖出/买入提交开关打开做一次演练，演练完关闭。  
5. 把演练结果记入 `GPT工作记录.md` / `Grok工作记录.md`。

---

## 四、Grok / GPT 分工（避免冲突）

| 角色 | 自动交易相关 |
|------|----------------|
| **Grok** | SELL 队列、护栏、对账同步、通知 Outbox、卖出节拍 |
| **GPT** | BUY 预留/提交、策略引擎与配置、Dashboard 调度挂载、规则矩阵 |

跨边界（例如让 Dashboard 调用 `runSellAutomationTick`）需双方记录协商后再改。

---

## 五、一句话

**能自动，是因为队列和护栏在；能放心自动，是因为 Testnet 跑通且调度不依赖你一直开着网页。**  
当前处于「框架可自动 → 验收后才可无人值守」之间，请按阶段 3→4 推进，不要直接开生产。
