# 策略3.3代码核对与测试说明

## 核对原则
- 以用户确认的策略3.3 Excel为唯一规则依据；不从旧代码反推规则。
- 每项规则必须有配置、实现、单测/集成测试和UI证据；无测试证据标记未验证。
- 真实订单、余额和资金流程一律mock/dry-run；生产现货BUY/SELL与Simple Earn自动赎回保持关闭。

## 测试分层
1. 参数测试：积极型/保守型所有参数逐项断言。
2. 纯逻辑：评分、企稳、BTC状态、现金/组合额度、补仓、止盈、底仓、追踪止损。
3. 状态机：pending、claimed、submitted/unknown、reconcile_required、partial fill、terminal。
4. 成交账本：仅确认成交入账；重复fill幂等；冲突记录fail-closed。
5. 数据质量：未收盘周线、asOf错位、缺失指标、NaN/Infinity、重复/乱序K线、缓存过期、ticker缺失。
6. IndexedDB：并发标签页、重启恢复、事务中止、升级阻塞、配额耗尽。
7. UI：规则版本、数据as-of、信号价/执行价、许可拒绝原因、人工复核。
8. 回测：分形态、样本外、成本敏感性、退市样本、定投/买入持有基准。

## P0验收门槛
- 周线未收盘或关键数据不完整：不得产生有效买入许可。
- 交易日志/成交账本异常：禁止新增买入。
- 组合约束不能可靠计算：不得放行相关买入。
- 订单提交结果未知：转对账/人工复核，不自动重试。
- SELL底仓减仓未显式授权：拒绝。
- 部分成交只按真实成交数量记账。
- fill字段冲突：fail-closed并人工对账。
- 回测和样本外验收未通过：不得启用生产交易。

## 推荐顺序
P0-A策略参数对照；P0-B周线收盘与数据完整性、分离signalAsOf/executionPrice；P0-C组合风控和BUY预检；P0-D SELL状态机（Grok维护）；P1-A真实浏览器多标签页/重启/IndexedDB故障；P1-B历史回测；P1-C UI呈现与拒绝原因。

## 通过标准
全量测试与TypeScript检查通过；每个规则域有测试证据；回测覆盖工作簿指标；样本外及手续费滑点敏感性通过；计入现金闲置机会成本后优于定投基准。全部通过前保持“暂不上线”。
