## 6. 数据周期与完整性代码审查（新增）

### 已确认的实现事实
- `lib/binance.ts` 的 `fetchKlines` 直接映射 Binance 返回的周线行，没有依据 closeTime 过滤未收盘周线。
- `strategy/indicators.ts` 的 `closesWithPrice` 会把最后一根周线 close 替换成实时 ticker price。
- `strategy/engine.ts` 的周线 RSI、MA200、企稳条件均基于上述替换后的序列；企稳条件 1 又直接使用实时 price 与上周 high 比较。
- `lib/dashboard.ts` 同时使用 ticker price 计算市值、浮盈和策略输入价格。
- 因此当前信号实际是“周线历史 + 实时价格混合”，不是严格的“全部只用已收盘周线 close”。若当前 V3.3 仍要求只用已收盘周线，这属于 P0 规则偏差。

### 待进一步核查
- 服务层 stale cache / 部分数据失败时，是否能阻断所有可执行买卖信号，而不只是显示数据陈旧提示。
- K线时间戳、交易所周线边界、周线收盘确认时间与恐惧贪婪指数采样时间是否对齐。
- 历史长度不足、NaN/Infinity、零值、乱序/重复K线、异常OHLC、指标源不一致时，是否统一 fail-closed。
- 价格触发与周线评分是否应分离：周线收盘用于评分和结构条件；实时 ticker 仅用于下单前价格/滑点预检。

### 当前决策
- 暂不擅自改变策略触发语义，因为必须先确认 V3.3 最新原表是否允许实时价格触发。
- 在用户确认前，任何使用未收盘周线/实时 ticker 混合评分的风险都必须明确展示，不可宣称完全符合“周线收盘规则”。
- 推荐后续采用双时间语义：`signalAsOf`（最近已确认周线）与 `executionPrice`（最新现价），并在 API / 类型 / UI 中分开传递；不能通过覆盖 candle.close 混为一个数值。
